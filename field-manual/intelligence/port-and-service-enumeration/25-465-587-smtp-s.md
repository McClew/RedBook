# 25, 465, 587 - SMTP/S

The **Simple Mail Transfer Protocol (SMTP)** is a protocol utilised within the TCP/IP suite for the sending and receiving of e-mail. Due to its limitations in queuing messages at the recipient's end, SMTP is often employed alongside either [110-995-pop.md](110-995-pop.md "mention") or [143-993-imap.md](143-993-imap.md "mention"). These additional protocols enable users to store messages on a server mailbox and to periodically download them.

{% hint style="info" %}
Default port: 25, 465(SSL), 587(SSL)
{% endhint %}

In practice, it is common for e-mail programs to employ SMTP for sending e-mails, while utilising [110-995-pop.md](110-995-pop.md "mention") or [143-993-imap.md](143-993-imap.md "mention") for receiving them. On systems based on Unix, sendmail stands out as the SMTP server most frequently used for e-mail purposes. The commercial package known as Sendmail encompasses a POP3 server. Furthermore, Microsoft Exchange provides an SMTP server and offers the option to include POP3 support.

```bash
PORT   STATE SERVICE REASON  VERSION
25/tcp open  smtp    syn-ack Microsoft ESMTP 6.0.3790.3959
```

## Banner Grabbing

Initial identification of the SMTP service can be performed using [nmap](../../../toolbox/tooling/information-gathering/network-enumeration/nmap/ "mention") to pull version information and supported commands.

```bash
sudo nmap -sV -sC -p25 <TARGET_IP>
```

***

## Basic Enumeration

If the service is misconfigured, it may allow for user enumeration via the `VRFY` command. This can be tested manually via Telnet or [netcat.md](../../../toolbox/tooling/post-exploitation/netcat.md "mention").

* **Manual Verification:** Connecting to port 25 and issuing `VRFY <username>`. A `252` response typically indicates a valid user, while a `550` error indicates the user does not exist.
* **Automated Enumeration:** Tools such as `smtp-user-enum` can be used to automate this process against a wordlist to build a target list for subsequent brute-force attacks.
* **External Records:** In a real-world scenario, tools like `dig` or web-based services like MXToolbox should be used to identify MX (Mail Exchange) Records associated with the domain.
