# 123 - NTP

The **Network Time Protocol (NTP)** synchronises system clocks across a network. Beyond time drift, NTP servers can be a useful - and sometimes noisy - source of internal network information, and misconfigured ones are a well-known DDoS amplification vector.

{% hint style="info" %}
NTP listens on **UDP port 123**. Version 4 (RFC 5905) is standard; legacy `ntpd` installs may still expose the deprecated `monlist` query.
{% endhint %}

```
PORT    STATE SERVICE
123/udp open  ntp
```

***

## Cheat Sheet

| Command                                                    | Description                                                                                                                                                                             |
| ---------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ntpq -c readvar <TARGET_IP>`                              | Reads server variables — version string, OS, and configuration hints.                                                                                                                   |
| `ntpdc -c monlist <TARGET_IP>`                             | Lists the recent clients that have queried this NTP server — a direct source of internal IP addresses on an externally-facing NTP server. Only works if `monlist` hasn't been disabled. |
| `nmap -sU -p123 --script ntp-info,ntp-monlist <TARGET_IP>` | Nmap equivalent of the above two checks in one pass.                                                                                                                                    |

***

## `monlist` - Information Disclosure & DDoS Amplification

Older `ntpd` versions (pre-4.2.7p26) respond to an unauthenticated `MON_GETLIST` (`monlist`) request with up to the last 600 clients that queried the server:

```bash
ntpdc -n -c monlist <TARGET_IP>
```

This is doubly interesting:

* **Recon:** on an internet-facing NTP server, the returned addresses can reveal internal hosts that reach out to it, or other organisations/individuals using the same public time source.
* **Abuse:** `monlist` returns a response far larger than the request, making it a classic **UDP amplification** vector (amplification factors historically as high as \~200x) for spoofed-source DDoS attacks. Finding it enabled on a client's perimeter is a reportable finding on its own, independent of any info-disclosure angle.

***

## Automated

```bash
nmap -sU -p123 -sV --script "ntp-info,ntp-monlist" <TARGET_IP>
```
