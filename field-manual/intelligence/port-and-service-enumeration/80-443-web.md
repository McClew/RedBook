# 80, 443 - Web

**HTTP** and **HTTPS** are, by volume, the most commonly encountered services on any assessment. This page covers first-pass triage of a web service found during port/service enumeration; deeper technique-specific pages live under **Web Enumeration** and **Web Attacks**.

{% hint style="info" %}
HTTP defaults to **TCP port 80**, HTTPS to **TCP port 443** - but web applications are frequently found on non-standard ports (8080, 8443, 8000, 8888, 3000, etc.), so treat any unidentified open TCP port as a candidate for an HTTP probe.
{% endhint %}

```
PORT    STATE SERVICE
80/tcp  open  http
443/tcp open  https
```

***

## Cheat Sheet

{% tabs %}
{% tab title="Basics" %}
| Command                                                                       | Description                                                                                    |
| ----------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `curl -i http://<TARGET_IP>/`                                                 | Grabs headers and body in one shot; check `Server`, `X-Powered-By`, cookies, and any redirect. |
| `whatweb -a3 <TARGET_IP>`                                                     | Fingerprints CMS, framework, JS libraries, and server software.                                |
| `curl -s http://<TARGET_IP>/robots.txt`                                       | Often reveals disallowed paths worth checking directly.                                        |
| `curl -s http://<TARGET_IP>/sitemap.xml`                                      | Can reveal the site's full structure.                                                          |
| `nmap -p80,443 -sV --script http-title,http-headers,http-methods <TARGET_IP>` | Quick Nmap-based triage: page title, headers, and allowed HTTP verbs.                          |
{% endtab %}

{% tab title="TLS (443)" %}
| Command                                                        | Description                                                                                              |
| -------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `openssl s_client -connect <TARGET_IP>:443 -servername <HOST>` | Manual TLS handshake; also dumps the certificate (useful for hostnames in the SAN field).                |
| `sslscan <TARGET_IP>:443`                                      | Enumerates supported protocol versions and cipher suites.                                                |
| `testssl.sh <TARGET_IP>:443`                                   | Comprehensive TLS/SSL misconfiguration and vulnerability check (Heartbleed, POODLE, weak ciphers, etc.). |
{% endtab %}

{% tab title="Content Discovery" %}
| Command                                                                     | Description                                                  |
| --------------------------------------------------------------------------- | ------------------------------------------------------------ |
| `gobuster dir -u http://<TARGET_IP>/ -w <WORDLIST> -x php,txt,html`         | Directory/file brute-force.                                  |
| `ffuf -u http://<TARGET_IP>/FUZZ -w <WORDLIST>`                             | Faster alternative to Gobuster, supports advanced filtering. |
| `gobuster vhost -u http://<TARGET_DOMAIN>/ -w <WORDLIST>`                   | Virtual host brute-force where multiple sites share one IP.  |
| `ffuf -u http://<TARGET_IP>/ -H "Host: FUZZ.<TARGET_DOMAIN>" -w <WORDLIST>` | Same, via Ffuf header fuzzing.                               |
{% endtab %}
{% endtabs %}

## Certificate Recon (443 only)

TLS certificates leak hostnames even when DNS enumeration comes up empty - check the **Common Name** and every entry in **Subject Alternative Name (SAN)**:

{% code overflow="wrap" %}
```bash
echo | openssl s_client -connect <TARGET_IP>:443 2>/dev/null | openssl x509 -noout -text | grep -A1 "Subject Alternative Name"
```
{% endcode %}

Any additional hostnames found this way should be added to `/etc/hosts` and re-scanned - they often route to entirely different virtual hosts.

***

## Virtual Hosts

A single IP on 80/443 frequently hosts more than one site, distinguished only by the `Host` header. Compare response size/behaviour for a wildcard subdomain against a known-good one to filter noise before running a full vhost fuzz (see Content Discovery tab above).
